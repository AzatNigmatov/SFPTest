# Анализатор back-to-back soak-теста QSFP28

Скрипт разбирает логи приёмочного прогона 100G-трансиверов QSFP28 на коммутаторах
Juniper QFX5110-48S-4C и выдаёт Excel-книгу с детализацией и аналитический
PDF-отчёт с графиками и вердиктами по каждому модулю.

```bash
pip install -r requirements.txt
python3 sfp_soak_analyzer.py --log-dir . --out-dir ./report
```

## Методология

### 1. Дельты, а не «первое минус последнее»

Счётчики Junos (FEC, carrier transitions, input errors) кумулятивные и живут **на
порту**, а не на модуле: при ротации они не переезжают вместе с трансивером, а
`clear interfaces statistics` или пересоздание интерфейса обнуляет их посреди прогона.
Поэтому все метрики строятся на **поинтервальных дельтах**. Отрицательная дельта
трактуется как сброс счётчика, и такой интервал исключается.

### 2. Краевые окна монтажа

Установка и извлечение модулей оператором неизбежно дают link down, скачок carrier
transitions, обвал RX до «нет света» и лавину FEC-ошибок. Первые `--head-guard-min`
(по умолчанию 5) и последние `--tail-guard-min` (по умолчанию 15) минут каждого
захвата помечаются краевыми и исключаются из метрик надёжности и из статистики DOM.
На графиках они остаются видны — затенены серым, — а их содержимое выносится
в отчёт отдельными колонками `*_в исключённых интервалах`.

> На реальных логах этого репозитория эффект решающий: у `sw-b1 et-0/0/48` из
> 33 057 781 исправленной FEC-ошибки **33 050 372 пришлись на момент ротации**,
> а на 25 часов самого прогона — лишь 7 409. Без этого разделения модуль выглядел бы
> тяжёлым браком.

### 3. Интервал считается «грязным» и исключается, если

* на любом его конце линк не в состоянии Up;
* на любом его конце есть `Active defects`, отличные от `None`;
* произошёл сброс счётчика;
* интервал попал в краевое окно;
* длительность аномальна (пропуск в работе монитора — длиннее 3 медиан).

### 4. Гейт статистической состоятельности

Наклон тренда, снятый за 15 минут и приведённый к суткам, — это умноженный шум.
Если наблюдение короче `min_hours_for_drift` (6 ч), критерии дрейфа TX/RX/Bias не
применяются вовсе, а в обоснование добавляется явная оговорка. Аналогично перекос
между линиями не оценивается менее чем по 12 снимкам DOM.

## Критерии вердикта

| Вердикт | Условие |
|---|---|
| **В ЗИП** | 0 флапов, 0 FEC Uncorrected, 0 input/CRC/bit errors, pre-FEC BER ниже 1e-9, DOM строго в границах даташита, дрейф и перекос в норме |
| **Рабочий, не в ЗИП** | ошибок нет и линк стабилен, но поток FEC Corrected значим (BER 1e-9…5e-6), либо нестабилен, либо мал запас до нижней границы даташита, либо умеренный перекос/дрейф |
| **БРАК / Утилизация** | любые FEC Uncorrected > 0, флапы линка, input/CRC/bit errors, выход DOM за границы даташита, деградация мощности, лавинообразный рост Bias current, либо BER выше 5e-6 |
| **Нет данных** | не осталось ни одного пригодного интервала |

Оценочный pre-FEC BER считается как `(FEC corrected ошибок/с) / 103.125 Гбит/с`.
Ориентир: бюджет RS-FEC (Clause 91) ≈ 5e-5, порог «нет запаса» взят как 10 % от него.

Профиль границ даташита выбирается ключом `--optic`: `SR4` (по умолчанию), `LR4`,
`CWDM4`. На логах этого репозитория ток смещения 6–7,6 мА однозначно указывает на
VCSEL, то есть **SR4**.

### Логика ротации в 2 круга

* модуль «грязный» в **двух и более** кругах с разными партнёрами → **брак подтверждён**;
* модуль «грязный» в одном круге и чистый в другом → виновата **трасса**
  (патч-корд, загрязнение коннектора), модуль годен после перечистки;
* модуль «грязный» в единственном круге → **требуется повторный тест**.

Логика работает только при заполненной карте `modules_map.csv` — см. ниже.

## Серийные номера

**В логах их нет.** Ни `show interfaces ... extensive`, ни
`show interfaces diagnostics optics` серийных номеров не печатают, а
`show chassis hardware` в снимки не входил. Проверены и исходные файлы из истории
репозитория — там их тоже нет.

Поэтому связь «место → модуль» задаётся внешней картой:

```bash
# 1. Сгенерировать шаблон по фактическому составу логов
python3 sfp_soak_analyzer.py --write-map-template --map modules_map.csv

# 2. Заполнить колонку serial

# 3. Запустить анализ с картой
python3 sfp_soak_analyzer.py --map modules_map.csv
```

Без карты скрипт не падает: каждое место анализируется независимо под
псевдо-идентификатором `T1|sw-A|et-0/0/48`, а кросс-раундовые выводы отключаются
с явным предупреждением в консоли, в Executive Summary и в колонке «Вывод по ротации».

| Ключ | По умолчанию | Назначение |

| `--log-dir` | `.` | Каталог с логами |

поиска по коду.

## Отказоустойчивость

Ни одна ошибка в отдельном снимке или порту не прерывает разбор. Все замечания
копятся и выгружаются на лист **«Диагностика парсинга»** и в приложение PDF.
Проверено на: обрезанном на середине файле, неразбираемых метках времени, пустых
снимках, нечисловых значениях счётчиков, DOM без секций `lane`, мощности только
в `mW` или только в `dBm`, значениях `- Inf` и `Off`, пустом файле и файле,
не являющемся логом.

## Известные особенности данных этого репозитория

1. **Разные метки временных зон** — сторона A пишет `+05`, сторона B `UTC`, при этом
   стенные часы идут синхронно: метка зоны на одном из коммутаторов выставлена
   неверно. Корреляция концов линка выполняется по стенному времени; в отчёт
   добавляется соответствующая оговорка. Перед следующим прогоном стоит привести
   NTP и таймзону к единому виду.
2. **Счётчики между кругами не обнулялись**, причём неконсистентно: часть портов
   в круге 2 стартует с накопленных значений круга 1. На поинтервальных дельтах
   это не сказывается.
3. **Поля `FEC Corrected/Uncorrected Errors Rate` всегда равны 0** во всех снимках —
   скорость считается самим скриптом из дельт и Δt.
4. **`Input errors`, `CRC/Align`, `Bit errors`, `Errored blocks` равны 0 везде**.
5. **В круге 2 три линка (порты 48–50), а не четыре** — 6 модулей.
6. В круге 2 модули рапортуют одинаковый ток смещения по всем четырём линиям —
   на графиках кривые совпадают, это помечено подписью.
